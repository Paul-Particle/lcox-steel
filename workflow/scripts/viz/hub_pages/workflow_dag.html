Simplified rule graph. These are the rules; at run time each fans out over wildcards (scenario, area, route, tech, variant, dates…) into many jobs — one solve per run key, one report per scenario, and so on.

Overview vs Faithful: Overview draws only the defining dependency (the cutout) into each CF rule. Switch to Faithful to also draw the geometry parquets every CF rule (and cf_map) really declares, and the two rules that read config/scenarios.csv as a file — compile_report, for the variant each tech was solved with. config.yaml reaches the rules as params via lookup, and the scenario table also shapes the fan-out at parse time, so those stay annotations here rather than arrows.

Default target demo (and all) build the report + capacity bars. Dashed rules — plot_cf_map, plot_lcos_bars, plot_siting_map, plot_site_capacity_bars — are requested on demand. The grid parquets are temp(), deleted after the solve consumes them.

Runs offline: the demo ships a pre-sliced Victoria (AUS) cutout backup, so download_cutout needs no CDS download; an onstart hook also scrubs stray VM NUL bytes from sources before any rule runs.
